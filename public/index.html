🌱 MinTML - The Minimalistic HTML framework.

HTML called. It wants it's job back! Less framework. More HTML. The web already works. Let it. What if HTML was enough?

Meet MinTML, the HTML-first, zero-build, SPA, client-side, micro-framework. MinTML extends standard HTML instead of replacing it — clean, pure HTML, modern CSS, and vanilla JavaScript that run natively in the browser, no transpiler required. Routing, templating, and role-based visibility that get out of the way. Delete <script> and your page still works.

Quick example

Two lines of JavaScript. That's the whole router.

Mark sections with data-page, link to them with a normal hash link, and MinTML wires up the rest.


<script type="module">
  import MinTML from 'https://cdn.jsdelivr.net/npm/@mintml/mintml/dist/mintml.min.js';
  const app = new MinTML();
</script>

<header>
  <nav>
    <a href="#">Home</a>
    <a href="#about">About</a>
  </nav>
</header>

<main>
  <section id="home" data-page>Home content</section>
  <section id="about" data-page>About content</section>
</main>

Every [data-page] section is a page. Hash links toggle which one is visible — no router config. Strip the <script> tag and it's still valid, readable HTML. This site does exactly that — view source any time.

What's inside

A small toolbox — a micro-framework, not a mega-framework

🔀

Hash-based routing

Mark sections with data-page; navigation is driven by href="#id" links and window.location.hash. Built-in 404 handling included.

🛡️

Before-guards

Intercept a link or form submission, run async validation or confirmation logic, and decide whether navigation proceeds — with data-before.

🎭

Role-based visibility

Elements with data-show="admin,editor" show or hide automatically based on the app's current role.

🧵

Lightweight templating

<template> elements render anywhere with {{variable}} substitution — no DSL to learn.

🔎

DOM helpers

$, $$, and $id are exported as short, familiar wrappers around the query selector methods you already know.

📮

Form serialization

form2Object(form) turns a submitted form into a plain object, grouping repeated fields into arrays automatically.

Who's it for

Who is MinTML for?

MinTML is for applications that are too interactive to be a website, but too simple to need a framework ecosystem.

Not every web application needs a build pipeline, a component architecture, a state management library, and hundreds of dependencies. Sometimes you just want to build the thing.

MinTML is for developers who want to start with HTML, add a little JavaScript, and have a real client-side application without the ceremony.

🌱 Philosophy

HTML is the foundation, not an afterthought. A MinTML page should degrade gracefully — if you delete the script tag, you still have a working, semantic HTML document.

MinTML encourages standards-compliant, semantic markup: clean, pure HTML, modern CSS, and vanilla JavaScript that run natively in the browser — no transpiler, no compiler, no build step standing between your code and the platform. The micro-framework adds behavior on top of markup you'd write anyway; it doesn't ask you to learn a templating DSL, run a bundler, or restructure your project around it. This is the way the web was intended.

🏷️ Data attributes

MinTML reads a small set of data-* attributes already sitting in your markup.

AttributeWhereWhat it does
data-page<section>Marks a routable page. MinTML toggles data-page="active" / "previous" to control which one is visible.
data-before<a> / <form>Names a guard function (registered with app.before()) to run before navigation proceeds.
data-showany elementComma-separated list of roles allowed to see this element, e.g. data-show="admin,editor".

🧵 Templating

<template> elements are read once on load and removed from the DOM. Render them anywhere with {{key}} substitution:

<template id="card">Hello {{name}}</template>

<script type="module">
  el.innerHTML = app.render('card', { name: 'Todd' });
</script>

🛡️ Guards & roles

Register a guard, then reference it by name from any link or form:

app.before('confirmDelete', async ({ element, payload }) => {
  return confirm('Are you sure?');
});
<a href="#done" data-before="confirmDelete">Delete</a>

Roles work the same way — configure them up front, then flip the current role at runtime:

const app = new MinTML({ roles: ['guest', 'admin'] });
app.role = 'admin';

📖 API reference

ExportDescription
MinTML defaultMain class. new MinTML({ roles, errorPageId })
.navigate(id)Navigate to a page by id
.refresh()Re-run routing for the current hash
.before(name, fn)Register a guard used by data-before="name"
.filter(fn)Register a global route filter — return false or an HTTP status code to block navigation
.role / .rolesGet/set the current role and configured roles
.render(templateIdOrString, data)Render a <template> with {{key}} substitution
$(selector)document.querySelector shorthand
$$(selector)document.querySelectorAll shorthand, returns an array
$id(id)document.getElementById shorthand
